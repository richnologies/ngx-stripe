Enterprise apps often fail Stripe Elements because the CSP blocks the Stripe.js CDN or Element iframes. ngx-stripe injects https://js.stripe.com/{named-version}/stripe.js (for example endive on the latest line). Allow those hosts explicitly.

Prefer Stripe’s official CSP guidance and adjust to your policy engine. The snippet below is a starting point, not a complete production policy.

  • script-src — Stripe.js from https://js.stripe.com
  • frame-src — Element iframes and 3DS / bank redirects ( js.stripe.com, hooks.stripe.com)
  • connect-src — API calls to https://api.stripe.com

Full reference: Stripe CSP guide.

Most apps load Stripe.js with a plain CDN string. If your CSP enforces Trusted Types (require-trusted-types-for 'script'), ngx-stripe retries with policy ngx-stripe (Stripe CDN only). Allow that name in CSP, e.g. trusted-types angular angular#unsafe-bypass ngx-stripe, or load Stripe.js yourself before bootstrapping ngx-stripe.
