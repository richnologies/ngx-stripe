Enterprise apps often fail Stripe Elements because the CSP blocks the Stripe.js CDN or Element iframes. ngx-stripe injects https://js.stripe.com/{named-version}/stripe.js (for example dahlia on the latest line). Allow those hosts explicitly.

Prefer Stripe’s official CSP guidance and adjust to your policy engine. The snippet below is a starting point, not a complete production policy.

  • script-src — Stripe.js from https://js.stripe.com
  • frame-src — Element iframes and 3DS / bank redirects ( js.stripe.com, hooks.stripe.com)
  • connect-src — API calls to https://api.stripe.com

Full reference: Stripe CSP guide.

Most apps load Stripe.js with a plain CDN string. If your CSP enforces Trusted Types (require-trusted-types-for 'script'), ngx-stripe retries via Angular DomSanitizer so script.src gets a compatible value without changing the common path. You can also allow https://js.stripe.com in your Trusted Types policy or load Stripe.js yourself from the matching named CDN before bootstrapping ngx-stripe.
