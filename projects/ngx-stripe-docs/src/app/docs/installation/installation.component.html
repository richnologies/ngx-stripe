Welcome to the Ngx Stripe installation guide. This guide provides detailed instructions for integrating Ngx Stripe into your Angular project, ensuring you're set up for a smooth implementation.

Before proceeding with the installation, make sure to note the following prerequisites:

  • Versioning: ngx-stripe versions are {angularMajor}.{stripeJsMajor}.{patch} (for example, 22.9.x is Angular 22 + Stripe.js dahlia / @stripe/stripe-js v9). Pick the row in the table that matches both your Angular major and the Stripe.js train you want. Details: Pick your lane.
  • StripeJS Peer Dependency: ngx-stripe requires @stripe/stripe-js as a peer dependency for types. Keep its major aligned with the middle digit of ngx-stripe.

Change the header Docs lane picker to update this command. Latest lane defaults to npm install ngx-stripe @stripe/stripe-js.

To install a specific Angular / Stripe.js lane, use an npm dist-tag or pin a version from the table. For example, Angular 21 + dahlia:

Important Notes
  • Stripe.js named versions: Stripe.js ships named trains (acacia, basil, clover, dahlia, …) on a predictable schedule. ngx-stripe hardcodes the matching CDN script per line. See the Stripe.js versioning policy. Do not pass a legacy apiVersion into Stripe() on basil and newer — that option is unsupported on those trains.
  • Lazy Loading of StripeJS: ngx-stripe loads Stripe.js from the Stripe CDN when needed. If StripeJS is already present in the page, ngx-stripe will not inject it again.
  • Direct Loading of StripeJS: If you load StripeJS yourself, always use the Stripe CDN for the named version that matches your ngx-stripe line. Do not vendor a local copy of Stripe.js.
  • What ngx-stripe owns: Angular DI, Observables, and Element host components. Appearance, payment method options, and Element behavior come from Stripe.js — see Stripe’s docs when styling or configuring Elements.
